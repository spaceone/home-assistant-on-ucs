# home-assistant-on-ucs

UCS 5.2 Debian source package for Home Assistant **2026.2.3** with Docker Compose v1,
systemd, LDAP command-line authentication, Apache HTTPS/WebSocket reverse proxy,
UCR configuration, UCS groups, a DNS CNAME and a portal tile.

## Release policy

**The package is intentionally pinned to Home Assistant 2026.2 on UCS 5.2.**
For this repository, newer Home Assistant releases require migration to UCS 5.3
and a revised package. This is a **project support policy**, not a demonstrated
technical requirement of the upstream Home Assistant container: its application
version is normally independent of the UCS host version. Do not change the
`homeassistant/image` tag without reviewing and testing that compatibility policy.

## Build and installation

Build natively on UCS 5.2 with `debhelper-compat (=13)`, `univention-config-dev`
and `univention-join-dev` installed:

```sh
apt install dpkg-dev
cd home-assistant-on-ucs
apt build-dep -y .
dpkg-buildpackage -us -uc -b
sudo apt install ../home-assistant-on-ucs_*.*.*_all.deb
```

A Docker registry connection is required on the first systemd start to pull the
2026.2.3 image and to run `pip install ldap3` in the derived image.
The package depends on Bookworm's `docker-compose` v1 (`docker-compose` binary).

Before the join script on non-default installations, set:

```sh
ucr set homeassistant/domain=homeassistant.example.org
ucr set homeassistant/http-port=8124
ucr set homeassistant/ldap/host=ucs-dc.example.org
```

### Extending Home Assistant configuration

The package provides **two YAML inputs**:

- `/etc/home-assistant-ucs/configuration.default.yaml` is **generated by UCR** and contains package defaults such as the local and LDAP auth providers, `http.trusted_proxies`, and `default_config`.
- `/etc/home-assistant-ucs/configuration.local.yaml` is a **persistent, user-maintained** file shipped as a Debian conffile. UCR never overwrites local changes.

On upgrade from the original package, an existing unmanaged
`/var/lib/home-assistant-ucs/config/configuration.yaml` is migrated into the
local file **if the local file is still empty**. If both contain user settings,
initialization fails safely and requires manual reconciliation.

The helper `home-assistant-ucs-merge-config` merges the mappings recursively into
`/var/lib/home-assistant-ucs/config/configuration.yaml`, which is the actual
`/config/configuration.yaml` in Home Assistant. Local values take precedence:
**mappings are deep-merged; lists, scalars and explicit `null` replace defaults**.
The merger preserves HA YAML tags such as `!include`, `!secret`, and
`!include_dir_named` as tags. Included files referenced by these directives
must be placed in `/var/lib/home-assistant-ucs/config/` because Home Assistant
resolves these paths relative to the generated `/config/configuration.yaml`.

For example, create or edit `/etc/home-assistant-ucs/configuration.local.yaml`:

```yaml
homeassistant:
  name: My Home
http:
  ip_ban_enabled: true
  login_attempts_threshold: 5
logger:
  default: warning
automation: !include automations.yaml
```

The result keeps the generated authentication providers and trusted proxy,
while merging the local options. To replace the entire provider list or trusted
proxy list, define those lists explicitly in the local YAML.

Apply changes with:

```sh
home-assistant-ucs-apply
```

`home-assistant-ucs-init` also regenerates the effective configuration during
service startup. The YAML is parsed before atomically replacing the
previous configuration; malformed YAML fails without damaging the last good
file. Do not edit the generated `/var/lib/.../configuration.yaml` directly:
its content is managed. Back up `configuration.local.yaml` and the complete
`/var/lib/home-assistant-ucs/config/` directory (including secrets and `.storage`).

To avoid a hard-coded proxy mismatch, both the Docker network and Home
Assistant trusted proxy are derived from the same UCR settings:

```sh
ucr set homeassistant/docker/subnet=172.29.84.0/24 \
        homeassistant/docker/gateway=172.29.84.1
home-assistant-ucs-apply
```

Choose an unused range. Changing the range recreates the Compose network.
The default (`172.29.83.0/24`, `172.29.83.1`) remains for compatibility with
the earlier prototype but is **not** assumed suitable for every installation.


## LDAP

Uses the built-in `command_line` authentication provider and a standalone Python
script with `ldap3`. The Dockerfile installs a pure-Python dependency
inside the container. The command receives `username` and `password` in process
environment variables, as prescribed by Home Assistant.

The plugin searches by `uid`, verifies LDAP group membership via `uniqueMember`,
then binds using the user's own DN and password over StartTLS (default UCS
OpenLDAP `7389`) or LDAPS (`7636`). The script emits `group = system-users` or
`group = system-admin` only after successful authentication.

**LDAP search bind credential:** UCS normally disables anonymous LDAP search.
The default configuration mounts `/etc/machine.secret` read-only and uses the
UCS machine account DN for an LDAP search bind. This exposes a sensitive machine
credential to the container, which is a security tradeoff. **For production,
prefer a separate read-only service account**, set its DN with
`homeassistant/ldap/binddn`, and replace that one volume mount with a dedicated
secret file. Do not commit passwords. The package includes a UCS machine-password-change hook that recreates the
container after password rotation, because a bind-mounted file may continue to
refer to an old inode after UCS replaces `/etc/machine.secret`. There is no
persistent credential copy or Gitea-style database reconciliation.

The `homeassistant-users` group grants login access, and membership in
`homeassistant-admins` grants initial Home Assistant admin role. Admins do not
need membership in the user group. **Home Assistant only applies `meta.group`
on first login.** Later UCS group changes do not automatically change the role
on existing HA accounts. You must update affected accounts in the HA UI or
build a supported reconciliation mechanism. There is no generic Home Assistant
built-in LDAP user/group synchronization equivalent to Gitea's.

The built-in `homeassistant` auth provider is retained as an emergency fallback.
Create a local owner through initial onboarding before relying on LDAP.

## HTTPS / WebSockets

The UCR Apache template includes the requested `ProxyPass /api/websocket`
route and forwarded protocol/real IP headers. It expects a certificate valid
for the configured DNS name. The default UCS host certificate may not cover
the alias: provide an appropriate SAN certificate before production use.

The package uses a configurable Docker bridge and gateway, shared with the
UCR-generated `http.trusted_proxies` default. Ensure the selected subnet does
not collide with existing Docker or LAN networks.
The HTTP host port binds to `127.0.0.1` only. The UCS firewall rule is therefore
not needed for normal HTTPS access through Apache. Direct HTTP exposure is
opt-in only, and requires modifying the Compose bind address and firewall rule.

## Integrations and runtime limits

- Using bridged networking means Zeroconf/mDNS/SSDP discovery may not work.
  Host networking would improve discovery but exposes port 8123 and requires
  reviewing other services, Apache and firewall rules.
- Home Assistant Container has no Supervisor or add-on store. External MQTT,
  Zigbee2MQTT, ESPHome, databases, and similar integrations run separately.
- USB devices, Bluetooth and DBus are not passed into the default container.
  Add devices and mounts deliberately for integrations that require them.
- Keep time synchronization, timezone and backups of the entire `/config`
  directory including `.storage`, keys and long-term statistics.
- Do not use a broadly trusted proxy range: the proxy is set to the configured
  bridge gateway. The reverse proxy must set `X-Forwarded-For` correctly.
- Verify user creation and admin assignment on a staging environment before
  granting access on production systems.
- Review the risk of command-line auth provider passwords being carried in
  environment variables readable to sufficiently privileged local processes.
- Docker's port publishing can bypass ordinary UCS INPUT filtering.
- The icon is an original simple SVG created for this packaging repository;
  it does not contain or claim to be the upstream Home Assistant trademark.

## Verification

```sh
systemctl status home-assistant-ucs.service
docker-compose -p home-assistant-ucs -f /opt/home-assistant-ucs/compose.yaml ps
journalctl -u home-assistant-ucs.service -n 100 --no-pager
apache2ctl configtest
```

Manual LDAP check after provisioning a bind credential:

```sh
docker-compose -p home-assistant-ucs -f /opt/home-assistant-ucs/compose.yaml \
  exec -T homeassistant /usr/local/bin/homeassistant-ucs-ldap-auth
```

The command requires the `username` and `password` environment variables and
will return exit code 1 if they are missing (expected). For an interactive test,
pass these values through Docker `exec -e` with caution and do not log passwords.
